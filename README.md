## 开发计划

> 赛题：第四题「字源」——一个汉字的形·音·义溯源（★★★★）
> 目标：输入汉字，生成字形演变、构形解读、义项时间轴、读音流变、60 秒口播文案与可分享字源卡；支持一次 10 字的批量出卡。

### 技术方案

- Vue 3 + Vite + TypeScript + vue-router（hash 路由，纯静态部署，无后端）
- papaparse：解析带 BOM 的 CSV；three：首页 3D 场景（动态加载）；html-to-image：字源卡 PNG 导出
- Vitest：数据层与校验逻辑测试

### 数据现状

- 数据包实际覆盖 **60 字**、292 张字形图；其中 8 字（漢、湛、環、賜、賞、道、過、城）无甲骨文帧，界面显示「未见著录」占位，不以其他字形顶替。
- CSV 均为 UTF-8 带 BOM；`年代` 与 `对应义项` 是自由文本，需解析后排序、关联。
- 赛题要求的 `char_truth.json`（10 字核验真值）未随数据包提供，改用「全量一致性自检 + 数据核验页」替代一致率验收，并在本文件和关于页说明。

### 分阶段任务

#### 阶段 0：数据与脚手架

- [ ] 初始化 Vite + Vue 3 + TypeScript 工程与 hash 路由

- [ ] CSV 解析、BOM 处理，建立繁体字头 / 简体 / 拼音三个索引
- [ ] 年代排序（含「西周—春秋」等区间）、多音字「对应义项」解析、缺帧标记
- [ ] Vitest 覆盖：CSV 解析、年代排序、简体转繁体、义项关联

#### 阶段 1：核心字源卡

- [ ] 首页搜索（繁简皆可）+ 热门字 + 未收录友好提示
- [ ] 字形演变：横向滑动对比，每帧标注年代、字体名称、来源页、许可；缺帧占位
- [ ] 构形解读：造字法（象形/指事/会意/形声）、构形解析一句话、《说文》依据、数据来源、争议「一说」徽章

- [ ] 读音流变卡：现代读音 / 广韵反切 / 中古声母·韵目·声调 / 郑张上古拟音，多音字按义项分列并联动高亮

### 验收自查

- 字形图像每字 ≥4 帧（52 字 5 帧、8 字 4 帧），非现代字库冒充
- 每个义项展示书证原句与出处，可回溯来源
- 19 个多音字的读音与义项对应无错配（解析后逐条校验）
- 口播文案按 4.2 字/秒估算落在 50–70 秒，内容与字源卡一致
- 真值一致率：因 `char_truth.json` 缺失，使用 `/validate` 页面的全量自检代替，并在路演中说明

### 验证方式

```bash
npm install
npm run dev        # predev 自动同步数据
npm run test       # 数据层与校验测试
npm run typecheck
npm run build && npm run preview
```

浏览器手工验收：输入「行」验证三读音与义项对应、输入「漢」验证缺帧占位、输入未收录字验证提示、批量 10 字（含 1 个未收录）、谜题解锁、字族跳转、分享卡 PNG 导出、减少动态效果模式。

### 主要风险与对策

- 真值缺失导致无法按原样计算一致率：核验页 + 全量自检 + 文档明示，不伪造数据。
- Three.js 低端机卡顿：动态加载、离屏暂停、DPR 上限、静态降级。
- 分享卡导出失败（字体/跨域/滤镜）：导出节点避开 `backdrop-filter`，预加载图片与字体，提供重试。
- 中文路径构建后 404：统一 `encodeURI` 与 `BASE_URL` 拼接，dev 与 preview 双环境验证。
- 自由文本字段解析异常：解析失败降级展示原文，并由测试与校验页兜底。
