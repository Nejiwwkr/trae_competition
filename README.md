# 字源 · 一个汉字的形·音·义溯源

「AI x 文学」赛题第四题「字源」参赛作品。

输入一个汉字，展开它从甲骨文到楷书的字形长卷、六书构形、《说文》依据、按年代排列的义项流变、中古反切与上古拟音，并生成一段 60 秒口播文案和一张可分享的字源卡。另有 10 字批量出卡、字族联想、部件动画、现代例句与看形猜字。

- 纯静态前端，无后端、无运行时大模型调用。
- 数据只使用赛题官方《汉字形音义溯源数据包》，未核验的字不做推测性补齐。
- 60 字、300 条字形帧记录、172 条义项、82 条读音、292 张字形图。

## 快速开始

要求 Node.js 22+（开发时使用 Node 22.19 / npm 10.9）。

```bash
npm install
npm run dev        # 自动同步数据包到 public/data，然后启动 Vite
```

打开终端输出的本地地址（默认 `http://localhost:5173/`）。

```bash
npm run test       # 数据解析与全量一致性测试（19 项）
npm run validate   # 只跑数据核验测试
npm run typecheck  # Vue / TypeScript 类型检查
npm run build      # 生产构建（含数据同步）
npm run preview    # 预览构建产物
```

> `assets/【发放给参赛队伍】汉字形音义溯源数据包/` 必须保留。`public/data/` 是同步生成物，已加入 `.gitignore`，不入库。

## 主要功能

| 模块 | 说明 |
| --- | --- |
| 首页与查字 | 支持繁体字头、简体字、拼音（无声调）检索，未收录字给出明确提示 |
| 字形演变 | 甲骨文→金文→小篆→隶书→楷书，逐帧标注年代、字体、来源页与许可；缺帧如实显示「未见著录」 |
| 六书构形 | 造字法、构形解析、《说文》依据、数据来源；争议条目显示「一说」徽章 |
| 部件动画 | 22 个字的人工核验部件拆分（如 明=日+月、武=止+戈），其余字明确标注暂未标注 |
| 义项时间轴 | 本义/引申义/假借义按年代排序，附书证原句、出处与白话翻译 |
| 读音流变 | 《广韵》反切、中古声母/韵目/声调、郑张尚芳上古拟音、现代读音；多音字按义项分列并与义项联动高亮 |
| 60 秒故事 | 60 字各一条预生成文案，按 4.2 字/秒估算时长，支持朗读与复制 |
| 分享字源卡 | 3D 倾斜预览，`html-to-image` 导出 1080×1480 PNG，含来源与许可 |
| 批量生词本 | 一次 10 字，自动去重、逐字核对、单张/全部导出 |
| 字族 | 23 个形旁组 + 12 个声旁组，组内字可跳转完整字源卡 |
| 谜题 | 看甲骨文/金文四选一猜字，答对可进入完整字源卡，记录连击与正确率 |
| 数据核验 | 11 项一致性自检、造字法/义项分布、多音字与缺帧清单 |
| 关于 | 数据来源、许可、AI 参与方式、方法与边界 |

## 数据来源与许可

- **字形图像**：Wikimedia Commons 公有领域字形系列，逐帧来源页与许可见字形卡「来源」链接。该系列源数据主要溯自中央研究院小學堂字形演變資料庫等公有领域整理。
- **楷书呈现**：开源字体 Klee One（SIL Open Font License），仅用于展示，不作为书法范本或文字学证据。
- **义项与构形**：《说文解字》原文与近代古文字学通行考释，整理自赛题官方数据包。每条义项均附书证原句与出处。
- **中古/上古音**：《广韵》反切与声韵调；上古音采用郑张尚芳拟音系统。拟音是学术构拟，不是古音录音。
- 争议处保留「一说」，不把一家之言写成定论。

## AI 参与方式

- 工程实现由 AI 编程助手协作完成；文案、例句与部件标注由 AI 辅助起草。
- 所有书证、释义、年代、读音、造字法均以数据包字段为准，未引入数据包以外的书证。
- 部件动画只覆盖人工核验过拆分的字；未核验的字明确显示「暂未标注」。
- 运行时不调用任何大模型 API，所有内容静态随站点发布。

## 数据核验与已知缺口

- **`char_truth.json` 未随数据包提供**：无法按官方「构形 ≥80%、义项序 ≥90%」的人工真值一致率给出分数。项目以 `/validate` 页面的全量一致性自检替代，并在页面与文档中明确说明，不伪造核验结果。
- **8 字无甲骨文帧**：漢、湛、環、賜、賞、道、過、城。界面统一显示「未见著录」，不以金文或小篆顶替。
- **60 字而非题面所写的 30 字**：以实际数据包为准。
- **自由文本字段**：`对应义项` 包含「义项1、2」「全部义项」与自由说明三种写法，已分别解析、关联或原文展示。

`npm run test` 会读取磁盘文件，确认每一张非空字形图真实存在，并检查：

- CSV BOM、引号内逗号、空行过滤；
- 60 字 / 300 帧 / 8 个缺帧；
- 简繁映射、三读音「行」的义项关联、年代排序；
- 书证三要素、多音对应、造字法、故事字数（210–294，约 50–70 秒）；
- 字族成员与部件标注均指向已收录汉字。

## 验证方式

```bash
npm run test
npm run typecheck
npm run build
npm run preview
```

浏览器手工验收路径：

1. 首页输入「行」→ 详情页 5 帧字形、三读音切换、义项联动高亮、故事 50–70 秒、PNG 可下载。
2. 输入「漢」→ 甲骨文位置显示「未见著录」。
3. 输入「龘」→ 友好提示，不报错。
4. 批量粘贴 10 字（含 1 个未收录）→ 逐字状态正确，可导出。
5. 谜题答对 → 可进入完整字源卡；字族组内字可跳转。
6. 系统开启「减少动态效果」→ Three.js 不渲染动画，内容完整可用。
7. 390px 宽度下无横向溢出。
